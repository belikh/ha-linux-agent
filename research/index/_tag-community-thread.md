- [[cpu-performance-scaling-the-linux-kernel-documentation]] — CPU Performance Scaling — The Linux Kernel documentation — Kernel CPUFreq admin guide (author Rafael J. Wysocki, Intel, © 2017, current for 7.3.0-rc1). CPUFreq has three layers (core, scaling governors, scaling drivers); user space interface is /sys/devices/system/cpu/cpufreq/policyX/ per policy object, where a policy = set of CPUs sharing hardware P-state control. Generic sysfs attributes: affected_cpus, bios_limit, cpuinfo_cur_freq (hardware-reported KHz), cpuinfo_avg_freq (ARM AMU, ms timeframe), cpuinfo_min/max_freq, cpuinfo_transition_latency, related_cpus, scaling_available_frequencies, scaling_available_governors, scaling_cur_freq (last requested, may differ from actual), scaling_driver, scaling_governor (read-write — write a governor name to switch), scaling_max_freq/scaling_min_freq (read-write clamps, min must not exceed max), scaling_setspeed (userspace governor only). Governors: performance (max), powersave (min), userspace (manual via scaling_setspeed), schedutil (scheduler-integrated, PELT-based, f = 1.25 * f_0 * util / max, IO-wait boosting, rate_limit_us tunable, replacement for ondemand/conservative), ondemand and conservative (legacy workqueue-based with up_threshold/sampling_rate/freq_step tunables). intel_pstate driver bypasses the governor layer with its own algorithms. Global boost knob at /sys/devices/system/cpu/cpufreq/boost (0/1); legacy AMD cpb knob is per-policy-looking but actually system-wide and deprecated. Relevant to a Linux agent: read scaling_cur_freq/scaling_driver/scaling_governor for CPU telemetry; write scaling_governor/scaling_min_freq/scaling_max_freq for performance control, with per-policy granularity. `evergreen`
