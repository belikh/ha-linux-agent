- [[the-homie-convention]] — The Homie convention — Official Homie MQTT convention specification (homieiot.github.io, current published version v5.0.0, released 11 May 2025; CCA 4.0 licence; version selector also exposes v4.0.0 which Telegraf's homie-v4 layout implements). Defines an MQTT topic-tree convention for IoT devices: topic IDs lowercase a-z, 0-9 and hyphen only; recommended QoS 2; all messages retained unless stated; payloads UTF-8 strings with strict type rules (integer/float/boolean 'true'/'false' case-sensitive, enum, colour rgb/hsv/xyz, ISO-8601 datetime); empty strings represented as single 0x00 byte because MQTT treats empty payload as topic deletion. v5 replaces v4's per-attribute topics with a JSON $description document (homie/5/[device-id]/$description) describing nodes/properties/children, plus $state and optional $log. Device lifecycle is the load-bearing part for ha-linux-agent: five states — init, ready, disconnected (before clean disconnect), sleeping (before sleep), lost (badly disconnected; MUST be defined as the LWT for root devices; a root device going lost marks every child in its tree lost). Permanent device removal REQUIRES clearing retained topics with zero-length payloads, in order (state first, then attributes/values). Controllers cannot request values (pure pub-sub) — devices must re-publish regularly. This is the lifecycle model HA's own MQTT discovery borrowed from conceptually: an agent for jupiterOS must publish retained state, a true LWT, and an explicit clean-shutdown 'disconnected' state to get correct offline detection — and entity cleanup needs deliberate retained-topic clearing, matching the Feb 2026 community complaint about telegraf2hassio entities being undeletable. `review`
