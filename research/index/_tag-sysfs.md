- [[backlight-support-the-linux-kernel-documentation]] — Backlight support — The Linux Kernel documentation — Kernel backlight documentation (current for 7.3.0-rc1). Backlight sysfs attributes: brightness (R/W — the REQUESTED level), actual_brightness (RO — the level actually used by HW), max_brightness (RO). Interface at /sys/class/backlight/<backlight>/brightness and /sys/class/backlight/<backlight>/bl_power (power mode: 0 full on, 4 full off). Drivers must implement get_brightness() if HW doesn't support every brightness value, so actual_brightness is the readback truth. uevents are emitted on actual_brightness when backlight changes; hotkey/platform brightness changes require the driver to call backlight_force_update() to re-sync userspace (BACKLIGHT_UPDATE_HOTKEY vs BACKLIGHT_UPDATE_SYSFS reasons). backlight_type enum: RAW (hardware registers), PLATFORM (platform-specific interface), FIRMWARE (standard firmware interface) — userspace can make policy decisions based on type. For a fleet agent controlling kiosk brightness: write brightness for control, read actual_brightness for state truth (a write may be clamped or ignored by HW), max_brightness for the scale, and type for preferring firmware/native interfaces. - [[cpu-performance-scaling-the-linux-kernel-documentation]] — CPU Performance Scaling — The Linux Kernel documentation — Kernel CPUFreq admin guide (author Rafael J. Wysocki, Intel, © 2017, current for 7.3.0-rc1). CPUFreq has three layers (core, scaling governors, scaling drivers); user space interface is /sys/devices/system/cpu/cpufreq/policyX/ per policy object, where a policy = set of CPUs sharing hardware P-state control. Generic sysfs attributes: affected_cpus, bios_limit, cpuinfo_cur_freq (hardware-reported KHz), cpuinfo_avg_freq (ARM AMU, ms timeframe), cpuinfo_min/max_freq, cpuinfo_transition_latency, related_cpus, scaling_available_frequencies, scaling_available_governors, scaling_cur_freq (last requested, may differ from actual), scaling_driver, scaling_governor (read-write — write a governor name to switch), scaling_max_freq/scaling_min_freq (read-write clamps, min must not exceed max), scaling_setspeed (userspace governor only). Governors: performance (max), powersave (min), userspace (manual via scaling_setspeed), schedutil (scheduler-integrated, PELT-based, f = 1.25 * f_0 * util / max, IO-wait boosting, rate_limit_us tunable, replacement for ondemand/conservative), ondemand and conservative (legacy workqueue-based with up_threshold/sampling_rate/freq_step tunables). intel_pstate driver bypasses the governor layer with its own algorithms. Global boost knob at /sys/devices/system/cpu/cpufreq/boost (0/1); legacy AMD cpb knob is per-policy-looking but actually system-wide and deprecated. Relevant to a Linux agent: read scaling_cur_freq/scaling_driver/scaling_governor for CPU telemetry; write scaling_governor/scaling_min_freq/scaling_max_freq for performance control, with per-policy granularity. `evergreen`
- [[generic-thermal-sysfs-driver-how-to-the-linux-kernel-documentation]] — Generic Thermal Sysfs driver How To — The Linux Kernel documentation — Kernel generic thermal sysfs driver HOWTO (Sujith Thomas & Zhang Rui, Intel, © 2008; current for 7.3.0-rc1). Userspace thermal interface lives under /sys/class/thermal: thermal_zone[0-*] directories expose type, temp (millidegrees, e.g. 37000 = 37°C), mode, policy (governor, e.g. step_wise), available_policies, trip_point_[0-*]_temp/_type/_hyst, emul_temp, plus PID tuning knobs (sustainable_power, k_po/k_pu/k_i/k_d, integral_cutoff, slope, offset). cooling_device[0-*] expose type, max_state, cur_state, and stats/ (time_in_state_ms, total_trans, trans_table — cooling statistics). Zone-to-cooling-device binding via cdev[0-*], cdev[0-*]_trip_point, cdev[0-*]_weight. A parallel hwmon interface appears under /sys/class/hwmon/hwmon[0-*] (name, temp[1-*]_input, temp[1-*]_critical) when no_hwmon is false. Critical trip crossing triggers orderly power-off/reboot, then forced, then emergency_restart() — thermal framework shuts the box down itself. For an agent: temp + trip points give thermal telemetry; cur_state/max_state give fan/throttle state; the thermal core's own shutdown behaviour bounds what agent-level alerting can add. `evergreen`
