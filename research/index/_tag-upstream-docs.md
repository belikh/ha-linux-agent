System users occupy 1-999 (privilege-separated daemons), regular users 1000-60000. systemd special ranges: 61184-65519 for DynamicUser= allocations (nss-systemd synthesises userdb records so resolution works without /etc/passwd), 60001-60513 systemd-homed users, 60578-60705 dynamic greeter users, 524288-1879048191 systemd-nspawn container ranges, 2147352576-2147418111 foreign-OS-image UIDs. - [[dbus-daemon]] — dbus-daemon — Upstream dbus-daemon(1) man page: authoritative reference for D-Bus message bus daemon configuration. Session-vs-system bus distinction: <type>session</type> sets DBUS_STARTER_BUS_TYPE=session and DBUS_SESSION_BUS_ADDRESS to the bus address in activated clients; <type>system</type> sets DBUS_SYSTEM_BUS_ADDRESS (normally well-known anyway). Recommends one session bus per (user, machine) pair shared between that user's login sessions. Per-user service directory resolved via /run/user/1000/dbus-1/services when XDG_RUNTIME_DIR is set — the mechanism by which user-session D-Bus services are discovered. <listen>unix:path=...</listen> configures the socket address. Well-known session bus policy defaults: allows any connection to send/receive any message and own any name — permissive by design, so the session bus must not be exposed; system bus uses /etc/dbus-1/system.d policy files. Load-bearing for the fleet agent D-Bus question: a system service wanting to reach the session/user bus must be told the address (DBUS_SESSION_BUS_ADDRESS) explicitly since it is per-user and lives under the user's XDG_RUNTIME_DIR. `review`
- [[dbus-launch]] — dbus-launch — Upstream dbus-launch(1) man page: the historical X11-session tool that starts a session bus and sets DBUS_SESSION_BUS_ADDRESS in the environment. Documents --sh-syntax/--csh-syntax/--binary-syntax address output, --exit-with-session lifetime binding, and that dbus-launch is designed for one-per-login-session use in X clients' startup scripts. Superseded on modern systemd systems where the session bus is a systemd user service whose address is exported as /run/user/1000/bus (via the dbus.socket/dbus.service user units), but still the canonical reference for how DBUS_SESSION_BUS_ADDRESS gets populated in a classic session. Supports the parent note's chain: a system-level service does not inherit this variable — it is only set inside the user's login/systemd --user environment. `review`
- [[systemdexec]] — systemd.exec — Upstream systemd.exec(5) man page (latest): authoritative reference for service execution configuration. User=/Group= are ONLY available for system services and root's user services — for user services of any non-root user, switching identity is not permitted (the only valid setting is the user the manager runs as), so a fleet agent cannot drop privileges from inside a user service. DynamicUser= allocates a transient UID/GID pair from range 61184-65519 at start, releases at stop, implies RemoveIPC=, NoNewPrivileges=, RestrictSUIDSGID=, ProtectSystem=strict, ProtectHome=read-only; critically 'currently incompatible with D-Bus policies, thus a service using this option may currently not allocate a D-Bus name' (calling other services still works) — rules DynamicUser out for an agent that must own a D-Bus/HA connection name. AmbientCapabilities= (v229+) adds caps to the ambient set for unprivileged execution and automatically sets keep-caps SecureBits; in per-user service manager instances it requires PrivateUsers= (unprivileged userns) support. CapabilityBoundingSet= constrains the bounding set. Credentials (LoadCredential=/SetCredential=) let privileged data be passed into unprivileged services — 'particularly useful in combination with DynamicUser=' `review`
- [[systemdspecial]] — systemd.special — Upstream systemd.special(7) man page: documents special units in both system and user manager instances. User-manager special units: default.target is the main target of the user service manager (analogous to multi-user.target for the system instance, but a real unit not an alias; v242+); capsule@.target (v255+) for capsule service managers; passive targets graphical-session.target (active while any graphical session runs; services should declare PartOf=graphical-session.target to stop with the session), plus exit.target, shutdown.target, sockets.target, timers.target, paths.target.
