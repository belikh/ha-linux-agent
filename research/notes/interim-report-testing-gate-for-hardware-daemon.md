# Interim report: testing-gate-for-hardware-daemon

**Locus question:** What concrete CI test design gates the reliability fixes — ephemeral-broker restart simulation mid-test (the exact bug class), birth-message rediscovery tests without a full HA, a runNixOSTest for the NixOS module, the zbus session-bus CI workaround, and sysfs tempdir mocking — for a workspace currently at 3 tests in 12 crates?
**Flavor:** technical (convergent)
**Register:** advocate, deep inference

## What the corpus already said

The width sweep assumed testcontainers as the harness: [[testcontainers-mosquitto-module]] + [[mosquitto-in-testcontainers_modulesmosquitto-rust]] document the Rust module API precisely — `cargo add -F mosquitto --dev testcontainers-modules`, `testcontainers_modules::mosquitto::Mosquitto::default().start()`, `broker_url = format!("{}:{}", get_host().unwrap(), get_host_port_ipv4(1883).unwrap())` (docs.rs 0.15.0, feature-gated, "Starts a MQTT broker without authentication", `with_startup_timeout` default 60s) — and [[github-testcontainerstestcontainers-rs-modules-community-community-maintained-mo]] adds the mechanics: testcontainers re-exported with aligned version, SyncRunner behind `blocking`, module defaults overridable via ContainerRequest (`with_tag`, `with_env_var`). [[feature-add-mosquittocontainer-mqtt-issue-568-testcontainerstestcontainers-pytho]] shows Mosquitto-in-testcontainers support is recent and thin across ecosystems (Python only gained it May 2024, via community contribution — claims file: "first-class MQTT-broker-in-tests support is a recent, thinly-maintained facility"). [[github-dbraun1991mqtt-test-testing-the-mqtt-mosquitto-client-v2018-using-testcon]] contributes the one hard-won implementation lesson: hardcoded broker URL vs ephemeral port is the exact bug that makes MQTT container tests fail ("The test fails on client.connect") — always derive the URL from the harness, never `tcp://localhost:1883`. [[hivemq-is-now-available-in-testcontainers]] gives the rationale vocabulary: "sharing the deployment across multiple tests can cause unwanted interference between them and produce unexpected results and flaky tests" — per-test exclusive broker, ephemeral persistence, auto-delete. [[github-z-galaxyzbus-rust-d-bus-crate-github-2]] carries the zbus CI constraint verbatim: "Integration tests of zbus crate currently require a session bus running on the build host." [[mocking-stdfs-for-unit-tests-help-the-rust-programming-language-forum]] settles the sysfs-mocking approach: std::fs "is a module, not a trait", so no direct substitution — tempfile's tempdir (auto-deleted on scope exit, tmpfs-backed) + trait/root-path abstraction is the canonical pattern. [[tempfile-rust]] supplies the primitives and caveats (TempDir cleanup relies on destructors; unix periodic tmp cleaners can unlink named temp files — irrelevant for sub-second tests). [[nixos-manual]] confirms `runNixOSTest` from `pkgs.testers` exists for out-of-tree projects. [[mosquittoconf-man-page-eclipse-mosquitto]] carries the decisive broker fact: `allow_anonymous` "Defaults to false, unless no listeners are defined in the configuration file, in which case it is set to true, but connections are only allowed from the local machine" — a bare `mosquitto -p <port>` is a zero-config, local-only, anonymous ephemeral broker. [[dbus-daemon]] gives the private-bus spawn mechanics: `dbus-daemon --session --print-address[=DESCRIPTOR] --print-pid --config-file=FILE`, socket path configurable via `<listen>unix:path=...</listen>`.

## What the new sources say

**nixpkgs ships a Mosquitto NixOS test to crib from** [[mosquittonix]] — `nixos/tests/mosquitto.nix` exists at master (audited absence resolved: it does NOT need to be written from scratch). It is a 3-node test (`server`, `client1`, `client2`) with the broker configured entirely through `services.mosquitto` (listeners on 1888/1889/1890, per-listener `users` with `password`/`passwordFile`/`acl` (`"read ${topic}"`, `"write ${topic}"`), `omitPasswordAuth` + `settings.allow_anonymous = true` with `"pattern read #"`). Readiness: `start_all()` then `server.wait_for_unit("mosquitto.service")`. Clients: `environment.systemPackages = with pkgs; [ mosquitto ];` wrapping `mosquitto_pub`/`mosquitto_sub -V mqttv311 -h server -p <port> -u <user> -P <password>` in Python helpers, with a race-free subscribe-then-publish assertion pattern: `parallel(...)` a `client1.succeed(subscribe("-i <uuid>", "reader"))` against `wait_uuid(...)` → `client2.succeed(publish(...))` via `server.wait_for_console_text(uuid)`.

**The out-of-tree runNixOSTest invocation** [[nixos-manual-2]] (NixOS manual "Calling a test", chased from the nixpkgs manual cross-reference): `let pkgs = import <nixpkgs> {}; in pkgs.testers.runNixOSTest { imports = [ ./test.nix ]; defaults.services.foo.package = mypkg; }` — the flake's own package injected into all nodes via a `defaults` block; "runNixOSTest returns a derivation that runs the test"; normal builds run **headless in QEMU** (interactivity opt-in via `.driverInteractive` + the `interactive` submodule); `copy_from_host(source, target)` ships files into the guest. [[nixpkgs-reference-manual]] adds the exact contract: runNixOSTest "behaves exactly like the NixOS runTest, except it also assigns this Nixpkgs package set as the pkgs of the test" — and its own cross-ref names the out-of-tree pattern as the NixOS manual's territory. The VM-vs-container trade-off is documented: containers are faster/lighter for CI; VMs are required for systemd namespacing options (`ProtectSystem=`, `MountAPIVFS=`), setuid, and kernel features — decisive here, since the agent's unit hardening and sysfs paths must be exercised for real.

**The crane cargoTest wiring** [[apimd]] (crane API.md): `cargoTest :: set -> drv` — "Except where noted below, all derivation attributes are delegated to `mkCargoDerivation`", which is "a thin wrapper around `stdenv.mkDerivation`" where "all derivation attributes are passed straight through" — so `nativeBuildInputs`/`buildInputs` from `commonArgs` apply to the test derivation directly (crane auto-appends cargo/rustc/rsync/zstd to whatever the caller specifies). Defaults: `buildPhaseCargoCommand = "cargo test --profile release"`, `cargoExtraArgs = "--locked"`, `cargoTestExtraArgs = ""`, `pnameSuffix = "-test"`; `cargoArtifacts` required (from `buildDepsOnly`). The ephemeral-broker hook surface: the check phase "will run `preCheck` hooks, log and evaluate `checkPhaseCargoCommand`, and run `postCheck` hooks" — preCheck/postCheck are the sanctioned start/stop points for a harness that needs setup/teardown inside the check. `cargoClippy`'s `cargoClippyExtraArgs` default `"--all-targets"` with documented purpose "deny specific lints" — where the already-present `-- --deny warnings` sits.

## Evidence synthesis

### The harness decision: mosquitto subprocess, NOT testcontainers

The corpus's testcontainers material is API-complete but runtime-blind. The audited ground truth is dispositive: no docker or podman on callisto, no container runtime in any jupiterOS host config, and Nix remote builders cannot expose Docker sockets inside build sandboxes anyway. A testcontainers gate would be dead on arrival — `nix flake check` builds on remote NixOS builders, where the container runtime does not exist and cannot exist. The same properties the testcontainers module provides (per-test ephemeral broker, random port, auto-cleanup, no auth config) are obtainable from the mosquitto binary that the devShell ALREADY ships, via the documented no-config default: `mosquitto -p <port>` binds an anonymous, local-only listener (mosquitto.conf(5): anonymous defaults true when no listeners are defined, "connections are only allowed from the local machine"). Per-test exclusivity (the [[hivemq-is-now-available-in-testcontainers]] anti-flake rationale: shared brokers cause "unwanted interference ... and flaky tests") is preserved by spawning one broker per test and deriving the URL from the harness port — the [[github-dbraun1991mqtt-test-testing-the-mqtt-mosquitto-client-v2018-using-testcon]] lesson ("The test fails on client.connect" from a hardcoded URL) holds identically. Port selection without a container-port-mapper: bind a `std::net::TcpListener` to `127.0.0.1:0`, read the assigned port, drop it, hand the port to mosquitto, TCP-probe for readiness with a `try_wait()` fail-fast if mosquitto died (port-collision race), retry up to 3×. Crane gives the binary to tests for free: `cargoTest (commonArgs // { nativeBuildInputs = ... ++ [ pkgs.mosquitto ]; })` — attributes pass straight through to the derivation (apimd), and the check runs with mosquitto on PATH for `std::process::Command` spawning. No preCheck hook is even needed — the per-test guard spawns/kills the broker itself, which keeps the harness inside the test code where the regression-guard comments live.

### The broker-restart test — the exact bug class, without a full HA

The mqtt-lifecycle sibling's defect list (D1 deafness-after-reconnect, D2 availability stuck offline, D3 no birth republish, D5 hung-backend starvation, D7 no graceful shutdown) is precisely a test matrix for a harness that can kill and restart a broker mid-test. The key move: the test's MQTT **observer is a second rumqttc AsyncClient** (rumqttc is already a workspace dependency — the observer is the same client stack as production, not a mock), subscribing to `ha-linux-agent/<device>/#` and `homeassistant/status`. `broker_restart_resubscribes_and_reasserts_availability` (D1+D2, THE bug class): start broker → spawn `Agent::run()` with a test config (poll interval 1s, jitter max 0) → observer sees retained availability "online" + discovery configs → `kill -9` mosquitto → restart it on the same port → publish a command topic message via the observer → assert the agent HANDLES it (proves ConnAck-driven re-subscribe, the exact line agent.rs:190 currently swallows as `Ok(_) => {}`) → assert a fresh observer subscribe reads retained "online" again (proves the D2 availability re-assert). `birth_message_triggers_discovery_republish` (D3): publish "online" to `homeassistant/status`, assert discovery configs re-arrive (requires the spec's jitter to be config-injectable — max 0 in tests). `sigterm_publishes_offline_then_disconnects` (D7): trigger the shutdown channel (the spec adds channel-based shutdown; in-process test, no real signal needed), assert retained "offline" arrives before `run()` returns. `hung_backend_doesnt_starve_sensors` (D5): register a backend whose `poll()` never returns + a healthy one; assert the healthy one's state still publishes within the poll interval. Every await wrapped in `tokio::time::timeout(5s)` — a reliability gate that can hang is not a gate.

These tests require a seam refactor of `Agent::run()` first: extract the setup task and poll loop into testable units parameterised on shutdown channel + jitter bound, keep `run()` as the composition. Without that seam the monolith is only testable as a black box with real signals — the black-box variant (spawn agentd, SIGTERM the child, assert offline publish via a mosquitto_sub watcher) is the fallback if the refactor stalls, but the channel seam is already implied by the lifecycle spec.

### The D-Bus layers: private dbus-daemon for plumbing, runNixOSTest for the real systemd signals

The zbus constraint ("Integration tests of zbus crate currently require a session bus running on the build host") does not apply verbatim to this repo's tests, because a Nix build sandbox has no session bus and no `/run` — but the same fix zbus's own CI uses works here: spawn a **private dbus-daemon per test binary** (`dbus-daemon --session --print-address --config-file=<tempdir-config>`, socket under the test's tempdir per dbus-daemon(1) `--print-address`/`<listen>unix:path=...</listen>`), set `DBUS_SESSION_BUS_ADDRESS` to the printed address, connect zbus. The `pkgs.dbus` buildInput already in commonArgs ships the binary. But the honest limit: a private bus has no `org.freedesktop.systemd1` — the unit-health backend (the privilege-ladder sibling's live-proven Subscribe()+JobRemoved design) cannot be exercised there. The real gate for that is the NixOS test: inside the QEMU VM a full system bus + real systemd exist, so `machine.systemctl(...)`-triggered job transitions can be asserted end-to-end through the agent's MQTT output. The system-bus unprivileged subscription is already live-proven on callisto (sibling evidence); the NixOS test turns that proof into a regression gate.

### The NixOS module gate — crib directly from nixpkgs' own mosquitto test

`nixos/tests/mosquitto.nix` [[mosquittonix]] provides the skeleton: one node with `services.mosquitto` + `environment.systemPackages = [ mosquitto ]`, `start_all()` → `wait_for_unit("mosquitto.service")`, then pub/sub assertions with a race-free uuid pattern. The agent's test adds the module under test: `services.ha-linux-agent.enable = true` with `settings.mqtt.host = "127.0.0.1"` on the same node (single node suffices — the kiosk failure mode is local: broker and agent on one host), `wait_for_unit("ha-linux-agent.service")`, then: (1) assert retained availability "online" arrives via `mosquitto_sub -C 1 -W 30`; (2) `machine.systemctl("restart mosquitto.service")` and assert the agent re-subscribes + availability returns online — the module-level replay of D1/D2, the exact "broker restart mid-operation" scenario as a system-level gate; (3) publish a birth message and assert discovery republish. Out-of-tree invocation from the NixOS manual [[nixos-manual-2]]: expose in the flake as a check — `checks.<system>.nixos-test = pkgs.testers.runNixOSTest { imports = [ ./nixos-test/agent.nix ]; defaults.services.ha-linux-agent.package = ha-linux-agent; }` (or via the flake's nixpkgs input). Headless by default; VMs (not containers) because the unit's systemd hardening + sysfs paths must be real. This test also becomes the gate for the service-model sibling's system-service refactor (User=io, Environment=DBUS_SESSION_BUS_ADDRESS=...) — one test pins both the module wiring and the unit shape.

### sysfs tempdir mocking = root-path injection + tempfile, not fs mocking

[[mocking-stdfs-for-unit-tests-help-the-rust-programming-language-forum]] closes the door on mocking std::fs ("std::fs which is a module, not a trait") and opens the canonical path: tempdir + abstraction. Concretely for backend-hardware: parameterise the crate on a sysfs root (constructor takes a `PathBuf` defaulting to `/sys`; the EACCES-warning `write_sys_file` at lib.rs:108-111 and the cpu-scan `map_or` at :117 both operate under it), add `tempfile` as a dev-dependency, then unit tests build a synthetic tree in `tempfile::tempdir()` — `thermal/thermal_zone0/temp` containing `45000`, `cpu0/cpufreq/scaling_governor` containing `performance`, etc. — and assert parsing to `SensorState` values plus the warn-not-panic behaviour on unwritable nodes. This matches the existing house style (pure `#[test]`s on shape functions) with the one addition of a fixture dir.

## Committed position

The concrete gate is a **seven-step, dependency-ordered ladder where step 1 is minutes and the fleet's entire reliability phase gets its definition of done at step 2**: (1) fix the clippy `map_or`→`is_some_and` at backend-hardware:117 so `nix flake check` can go green at all — the gate currently cannot gate; (2) add `craneLib.cargoTest` to the flake checks with `cargoArtifacts` from the existing `buildDepsOnly` — this wires the EIGHT existing tests (the locus premise of 3 is stale; 3 discovery + 5 launcher, all pure, all dev-dependency-free) into `nix flake check` for zero new code, the single cheapest reliability win available; (3) refactor backend-hardware to sysfs-root injection + add tempfile dev-dep + synthetic-tree unit tests; (4) extract the Agent::run seam (config-driven jitter bound, shutdown channel) that the lifecycle spec already requires; (5) add the mosquitto-subprocess harness (port-0-bind → probe-with-try_wait, Drop-guard kill, per-test exclusive broker, URL always derived from the harness port) + the five defect-named regression tests in `crates/core/tests/` — `broker_restart_resubscribes_and_reasserts_availability` (the exact bug class, kill -9 + restart on the same port, rumqttc observer client), `birth_message_triggers_discovery_republish`, `sigterm_publishes_offline_then_disconnects`, `hung_backend_doesnt_starve_sensors`, `decommission_zero_payload` — with mosquitto added to cargoTest's nativeBuildInputs, NOT testcontainers (audited ground truth: no container runtime exists on any jupiterOS host or Nix remote builder — a testcontainers gate would be dead on arrival, and the same anti-flake properties come free from `mosquitto -p <port>`'s documented anonymous local-only default); (6) add the private-dbus-daemon harness (spawn per test binary with `--print-address` into a tempdir, `DBUS_SESSION_BUS_ADDRESS` override) for zbus plumbing tests only — accepting it cannot test systemd signals; (7) add the runNixOSTest check (`imports = [ ./nixos-test/agent.nix ]` + `defaults.services.ha-linux-agent.package`), cribbed from nixpkgs' own `nixos/tests/mosquitto.nix` structure (wait_for_unit readiness, mosquitto_sub assertions, `systemctl restart mosquitto` mid-test to replay the broker-restart scenario at module level), VMs not containers so the unit's systemd/sysfs surface is real. The load-bearing reason for the harness decision: every alternative was eliminated by measured ground truth (no container runtime fleet-wide, no cargoTest in checks, no CI config at all), while the chosen ingredients — mosquitto in the devShell, dbus in buildInputs, nixpkgs' own mosquitto test as a crib, crane's pass-through nativeBuildInputs — are already shipped in this repo's flake today, so the gate costs zero new infrastructure, only wiring.

**Position:** Gate = `nix flake check` green with these checks added in order: clippy fix (map_or→is_some_and) → `craneLib.cargoTest` wiring the existing 8 pure tests → sysfs-root-injection unit tests via tempfile → mosquitto-subprocess integration tests in `crates/core/tests/` named per defect (broker-restart/re-subscribe, birth republish, SIGTERM offline, hung-backend isolation, zero-payload decommission) with a rumqttc observer client and port derived from the harness → private-dbus-daemon harness for zbus plumbing → runNixOSTest for the NixOS module cribbed from nixpkgs' mosquitto test including a mid-test `systemctl restart mosquitto`; testcontainers is explicitly rejected because no container runtime exists anywhere in jupiterOS.

- **Confidence:** high (80–85%). The harness decision rests on measured ground truth (missing runtimes, missing cargoTest, stale test count, failing clippy lint located at a specific line); the test designs rest on official documentation for every primitive (mosquitto.conf no-listener default, dbus-daemon --print-address, crane pass-through attrs, runNixOSTest imports/defaults shape, the nixpkgs mosquitto test itself). The 15–20% discount is for unverified runtime details: QEMU/KVM availability on the remote builders, the exact zbus-4-vs-5 API surface for address-based connections, and the mosquitto-child failure signature on port collision (design assumes `try_wait()` fail-fast covers it).
- **Boundary conditions:** This design holds for a NixOS-native fleet where `nix flake check` on remote NixOS builders IS the CI (jupiterOS has no GitHub Actions and no container runtime). If the project later gains hosted CI with Docker (e.g. GitHub Actions runners), testcontainers becomes viable and steps 5's harness could be swapped with the testcontainers-modules Mosquitto module without changing the tests' bodies — the test design is harness-agnostic except for the spawn guard. If the fleet adds a host with a container runtime, nothing else changes. The broker-restart test's same-port restart assumes mosquitto re-binds immediately after SIGKILL; if TIME_WAIT bites (it should not for LISTEN sockets, but), the harness retries the restart. The D-Bus private-bus layer is bounded to plumbing tests only — real systemd signal tests belong to the NixOS test and cannot be brought into cargoTest without systemd in the sandbox, which Nix does not provide.
- **What would change this position:** (1) Discovery that a jupiterOS host (or the CI story) gains Docker/Podman — then testcontainers-modules becomes the better harness for steps 5–6 (managed lifecycle, port mapping, no port-collision code) and I would swap the subprocess guard for `Mosquitto::default().start()`; (2) evidence that QEMU on the available builders is unusably slow (no KVM and TCG exceeding ~10 min per test) — then the runNixOSTest step drops to a nightly/manual gate rather than a per-check gate, with the cargoTest layer carrying the per-commit burden; (3) the zbus-4 address-based connection API not accepting the printed private-bus address (zbus 4 vs 5 differences) — then the private-bus harness needs the low-level `ConnectionBuilder` path or drops in favour of running those tests only in the devShell/VM; (4) the lifecycle spec's seam refactor being rejected (Agent::run stays a monolith) — then the broker tests go black-box (spawn agentd as a subprocess, real SIGTERM, mosquitto_sub observer), which is weaker but still gates D1/D2/D7.
- **Evidence weight:** 4 fetched primary sources (nixpkgs mosquitto NixOS test, nixpkgs manual testers chapter, NixOS manual "Calling a test", crane API.md) + ~10 corpus notes reused (testcontainers module docs ×2, mqtt-test repo, HiveMQ blog, zbus README, mocking-stdfs forum, tempfile docs, mosquitto.conf(5), dbus-daemon(1)) + direct repo/fleet ground truth (test inventory recount, flake checks audit, /etc/nix/machines, container-runtime absence, clippy lint located, agent.rs monolith audit) + 3 sibling interim notes' requirements absorbed (lifecycle defect list, service-model unit shape, privilege-ladder D-Bus proof). Zero contradicting sources; the only "opposing" candidate — testcontainers as harness — is refuted by ground truth, not by argument.

## Open questions

- **KVM on the remote builders** — callisto (root builder) and the kiosks: `/dev/kvm` presence unverified (thebe/adrastea were unreachable this session; `nix develop` failed on them). Determines whether the runNixOSTest check is a ~1-min gate or a slow TCG fallback. One command settles it: `ls -l /dev/kvm` on each builder.
- **zbus 4 (workspace pin) address-based connect API** — the vault's zbus docs are 5.19; zbus 4's `ConnectionBuilder`/`Connection::new` surface for a custom bus address needs a docs.rs pin to 4.x before writing the private-bus harness.
- **mosquitto child failure signature on port collision** — design assumes exit-with-error within the readiness probe window; verify the stderr line ("Address already in use") once, so the fail-fast check can match it.
- **Whether `nix flake check` running NixOS tests on kiosk builders while they are kiosk-duty machines** is acceptable operationally (CPU spike for the QEMU window) — an ops question, not a technical one; the nightly alternative exists.
- **agentd black-box fallback detail** — if the seam refactor stalls, the exact observer mechanics for asserting retained "offline" before process exit (mosquitto_sub with `-W` and a retained-read after SIGTERM) need a spike; not investigated this session.
- The corpus notes on testcontainers remain in the vault unused by this design — they become load-bearing only if the fleet gains a container runtime; flagging so the synthesizer doesn't cite them as if the design uses them.
